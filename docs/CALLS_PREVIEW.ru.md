# Meetily Calls Preview: звонки, CLI и локальный Codex

Это тестовый вариант Community, MIT. Исходный проект: https://github.com/Zackriya-Solutions/meetily; форк: https://github.com/YoungTeurus/meetily. База изменений: `a2cb62e827da7ef59f65064c97233efb2313878e` (0.4.1). Проверки конкретной реализации перечислены в [отчёте](implementation/verification.md); наличие исходников или успешная компиляция не подтверждают работу реального звонка.

## Установка и первый запуск

Используйте артефакты workflow **Meetily Calls Preview native builds**: DMG для Apple Silicon (macOS 14.2+, включая 14.8.5), NSIS/MSI для Windows 10 2004 build 19041+/Windows 11 x64 и отдельный `meetilyctl`. Команды воспроизводимой сборки: [native-build.md](implementation/native-build.md). Тестовые пакеты не являются подписанным и нотарифицированным релизом: macOS имеет только ad-hoc подпись, Windows — без подписи издателя.

Скачайте и распакуйте ZIP из раздела Artifacts нужного CI-прогона (GitHub может потребовать вход). На Mac откройте DMG и перенесите **Meetily Calls Preview.app** в Applications. Отдельный `meetilyctl` из архива положите, например, в `/Users/alice/Applications/meetilyctl`; после распаковки GitHub-артефакта восстановите право запуска командой `chmod +x /Users/alice/Applications/meetilyctl`. На Windows запустите один из установщиков — NSIS `.exe` или MSI — и положите отдельный `meetilyctl.exe`, например, в `C:\Users\alice\Tools\meetilyctl.exe`. CLI не устанавливается в PATH автоматически; используйте его абсолютный путь в конфигурации ниже. Доступность конкретных пакетов и сроки хранения указаны в [отчёте CI](implementation/verification.md).

Название приложения — **Meetily Calls Preview**, идентификатор — `com.youngteurus.meetily.calls`. Данные и модели находятся в отдельном каталоге приложения. Канал обновлений upstream отключён. Не направляйте два приложения на одну SQLite-базу и не меняйте пути моделей на каталог upstream.

Для переноса данных выберите явный импорт базы при первом запуске. Импорт разрешён только в ещё не использованный каталог preview. SQLite создаёт отдельный `import-backup-<uuid>.sqlite`, включая зафиксированные WAL-данные; проверяются целостность, нужные таблицы и верхняя версия миграций. Более новая схема и существующая база назначения отклоняются. Модели и аудиофайлы автоматически не перемещаются. Ссылки на старые аудиопапки могут требовать отдельного копирования; исходная база не открывается для записи.

1. Завершите первоначальную настройку и загрузите модель распознавания. **Summary Engine не нужен**: onboarding допускает транскрибацию без модели конспектов.
2. Для фиксированного русского языка выберите **Whisper**, модель с поддержкой русского (не `.en`) и `ru`. У Parakeet язык определяется автоматически; явный override отклоняется.
3. Выберите микрофон и выходное устройство. На macOS дайте разрешение на микрофон и запись системного звука; для обнаружения звонков дополнительно требуется Accessibility. На Windows проверьте доступ к микрофону в настройках конфиденциальности.
4. В настройках включите обнаружение Zoom/Discord. Обнаружение по умолчанию выключено. Запись начинается только по кнопке **Начать запись** или явной команде управления.

Системный звук — звук всего компьютера, включая музыку и другие приложения. Изоляция звука отдельного Zoom/Discord не заявляется. Закрытие главного окна скрывает его в tray; полный выход прекращает наблюдение. Автозапуск при входе в ОС включается отдельно и не начинает запись.

## Обнаружение и уведомления

[Матрица сигналов и ограничения](detection.md) описывает native Core Audio/Accessibility на macOS и WASAPI/UI Automation на Windows. Процесс приложения или активный микрофон сами по себе не подтверждают звонок. Читаются ограниченные элементы управления звонком. Неподдерживаемая версия интерфейса, отсутствие разрешения или недоступное дерево возвращают `unknown`, а отсутствующий адаптер — `unsupported`.

Исходные интервалы: подтверждение 3 секунды, ожидание кратковременной потери признаков 20 секунд. Они доступны в настройках. Mute, deafen и тишина сами по себе не завершают звонок. «Пропустить», закрытие предложения и ручная остановка подавляют повторное предложение для этой сессии. Кнопка старого уведомления повторно проверяет действительность сессии.

На Windows нажатие штатного toast открывает компактное окно действий работающего приложения. В macOS доступная Tauri notification API не предоставляет desktop activation callback, поэтому вместе с уведомлением сразу открывается компактное окно. Это явно обозначенное ограничение реализации, не подтверждённая поддержка action buttons. Отдельная настройка автоостановки по умолчанию выключена и применяется только к записи, привязанной к завершившейся обнаруженной сессии. Teams и браузерные встречи пока показаны как неподдерживаемые: универсальная активность браузера не определяет сервис.

## Локальные интеграции

В настройках включите **Разрешить чтение встреч**. Приложение запишет `integration.json` с адресом loopback и ключом чтения. Путь показан в настройках. Для управления записью отдельно включите **Разрешить управление записью**. Кнопка отзыва ключей инвалидирует старые credentials; отключение интеграций отклоняет все запросы.

Обычные пути файла:

- macOS: `/Users/alice/Library/Application Support/com.youngteurus.meetily.calls/integration.json`
- Windows: `C:\Users\alice\AppData\Roaming\com.youngteurus.meetily.calls\integration.json`
- Linux: `/home/alice/.local/share/com.youngteurus.meetily.calls/integration.json` (наблюдение звонков здесь `unsupported`).

CLI может использовать `MEETILY_INTEGRATION_FILE` для явного пути. Секреты не передаются в аргументах команд. Не публикуйте этот файл: он даёт доступ к локальным встречам. Он создаётся с режимом `0600` на Unix и ACL текущего пользователя на Windows. Gateway слушает исключительно `127.0.0.1`, проверяет ключ на каждом запросе, отвергает браузерные Origin/Sec-Fetch/неверный Host. CLI/MCP не открывают SQLite.

Протокол v1: POST `/v1/rpc`, заголовок `Authorization: Bearer …`, JSON `{ "method": "meetings.list", "params": { "limit": 20, "order": "desc" } }`. Ответ — `{ "result": … }` или `{ "error": { "code": "…", "message": "…" } }`. Мутации уже принятые backend не отменяются из-за обрыва HTTP/MCP-клиента.

## CLI

Все команды требуют запущенное приложение и включённые интеграции. Read-команды не запускают приложение скрыто.

```sh
meetilyctl doctor --json
meetilyctl status --json
meetilyctl devices list --json
meetilyctl recording start --name "Zoom meeting" --language ru --idempotency-key daily-sync
meetilyctl recording pause
meetilyctl recording resume
meetilyctl recording stop
meetilyctl recording wait --recording-id RECORDING_ID --until finalized --timeout 120
meetilyctl meetings list --limit 20 --json
meetilyctl meetings get MEETING_ID --json
meetilyctl meetings export MEETING_ID --format md
meetilyctl transcript get MEETING_ID --limit 200 --json
meetilyctl watch --events recording.started,recording.stopped,meeting.finalized --json
```

`recording start` возвращает `recording_id`, `meeting_id`, состояние и инициатора внутри объекта `recording`. Повторный start с тем же idempotency key возвращает прежнюю сессию; новый start во время существующей записи не создаёт второго рекордера. Повторный stop сообщает уже завершённое состояние. Идентификатор устройства выбирается через `--input-device` / `--output-device` (имя из `devices list`).

Остановка захвата и готовность текста различаются: `recording.stopped` означает прекращение захвата, `meeting.finalized` — завершение обработки и фиксацию встречи. Состояния `incomplete`/`failed` сохраняют доступный частичный текст; после аварии запись сама не возобновляется. `wait` имеет обязательный конкретный ID и конечный timeout; отмена ожидания не останавливает запись.

`watch` выдаёт NDJSON с сохранёнными ID событий, ISO временем и ID встречи/записи, продолжает чтение с cursor без повторов при переподключении. Ctrl+C завершает наблюдение. Пагинация `next_cursor` обязательна до `null`; для незавершённых встреч `partial=true`, обновление текста требует нового прохода с первой страницы. Страницы транскрипта фиксируют границу набора строк при первом запросе; новые сегменты не включаются в старый проход. После повторного распознавания меняется `transcript_revision`: прежний cursor возвращает `conflict`, и чтение нужно начать с первой страницы, чтобы не смешать версии текста. Время аудио отдельно в секундах, неизвестный спикер не определяется по догадке. Для исторических сегментов без wall-clock времени `timestamp=null`.

Подробнее об exit codes, флагах, SDK и конфигурации — [meetilyctl/README.md](../meetilyctl/README.md).

## MCP в локальном Codex

Установите `meetilyctl` на тот же компьютер, что Meetily. Этот stdio сервер работает с **локальным** приложением; облачная сессия разработки не подключается к вашему микрофону или SQLite.

Пример macOS в `~/.codex/config.toml` (замените `alice` и абсолютный путь):

```toml
[mcp_servers.meetily]
command = "/Users/alice/Applications/meetilyctl"
args = ["mcp", "serve"]
```

Пример Windows в `%USERPROFILE%\.codex\config.toml`:

```toml
[mcp_servers.meetily]
command = 'C:\Users\alice\Tools\meetilyctl.exe'
args = ["mcp", "serve"]
```

Альтернатива через CLI Codex:

```sh
codex mcp add meetily -- /Users/alice/Applications/meetilyctl mcp serve
codex mcp list
```

```powershell
codex mcp add meetily -- 'C:\Users\alice\Tools\meetilyctl.exe' mcp serve
codex mcp list
```

Конфигурация пользователя автоматически не меняется. MCP по умолчанию предоставляет только чтение; для `start_recording`/`stop_recording` одновременно нужны настройка управления в Meetily и `args = ["mcp", "serve", "--allow-control"]`. Подключение сервера не включает запись. Необязательный `save_summary` не реализован; готовый конспект остаётся в Codex, его можно сохранить вручную.

Пример запроса:

> Суммаризируй последнюю завершённую встречу. Через list_meetings выбери finalized по created_at, затем получи все страницы get_transcript. Составь краткий конспект, решения, задачи с исполнителями только если они явно названы, и открытые вопросы. Сохрани ссылки на аудиометки времени, неизвестных спикеров не угадывай. Если текст частичный, сообщи об этом.

Распознавание остаётся локальным. Когда Codex получает текст инструментом MCP, этот текст передаётся в выбранную вами модель/AI-сервис в рамках текущего запроса Codex. Это отличается от локального хранения и не требует встроенного OpenAI API-ключа в Meetily.

## Повторное распознавание и словарные подсказки

Откройте сохранённую встречу и выберите **Распознать заново** рядом с транскриптом. Требуется исходный аудиофайл встречи и установленная модель. Выберите другую модель Whisper или Parakeet; для Whisper можно явно указать `ru`. Новый запуск обрабатывает сохранённое аудио и не включает микрофон.

В настройках распознавания раздел **Подсказки для Whisper** сохраняет общий словарь: имена, компании, продукты, сокращения. Например: `HRMS`, `Гермес`, `Hermes`, `Яндекс Маркет`. Разделяйте слова запятыми или переносами строк. Общий словарь применяется к будущим запускам Whisper, включая запись и импорт аудио. В диалоге повторного распознавания можно добавить слова только для этого запуска; общий словарь от этого не меняется.

Лимит каждого поля — 1000 символов; Whisper получает до 224 токенов подсказки. Слова конкретного запуска идут первыми, затем общий словарь. Подсказки влияют на распознавание, но не гарантируют нужное написание и не являются командами для LLM. Parakeet не поддерживает этот механизм; в его режиме подсказки недоступны, язык определяется автоматически.

Перед запуском подтвердите замену текста. Во время обработки прежний транскрипт остаётся доступен; ошибка или своевременная отмена сохраняет его. Отмена проверяется между этапами и фрагментами; уже выполняющийся вызов модели может сначала закончиться. На этапе фиксации замены отмена уже недоступна. Только успешное завершение заменяет текст и аудиометки времени. Прежний конспект сохраняется с отметкой, что он относится к старому тексту; его можно сгенерировать заново отдельно. Одновременная живая запись и повторная обработка не запускаются, чтобы не менять используемую модель посреди записи.

## Ручная приёмка на обеих ОС

Проверять установленные пакеты отдельно на macOS 14.8.5 Apple Silicon и Windows 10/11 x64; записать точный OS build, версию Zoom/Discord, язык интерфейса, устройства, версию бинарников.

1. Запустить Zoom без встречи, Discord с текстовым чатом, видео/музыку, тест микрофона: не должно быть подтверждённого звонка.
2. Войти в Zoom с **выключенным микрофоном**, слушать собеседника **в наушниках**. После подтверждения получить предложение, проверить, что до кнопки аудио не записывается.
3. Нажать «Пропустить»: предложение не повторяется до конца сессии. В новом звонке начать запись, проверить микрофон и голос собеседника в итоговом аудио/тексте.
4. Повторить для голосового Discord; mute, deafen, 30 секунд молчания не должны завершить встречу. Проверить краткое переподключение, смену наушников/микрофона, сон/пробуждение, перезапуск дочернего процесса.
5. Открыть одновременно два приложения; разрешена одна запись. Выйти из одного: независимая ручная/CLI-запись продолжает работать. У связанной записи при выключенной автоостановке появится «Завершить и сохранить».
6. Остановить вручную во время звонка: повторного предложения нет. Нажать старое уведомление после выхода: запись не начинается.
7. Скрыть главное окно и перейти на другую страницу; начать/остановить из tray, CLI, MCP. Во время длинного последнего фрагмента остановить запись и дождаться `meeting.finalized`; текст в GUI, CLI и MCP должен совпасть.
8. Во время старта одновременно послать stop из другого клиента, затем несколько start с одинаковым ключом. Проверить отсутствие второй встречи/захвата. Прервать ожидающий CLI: backend завершает принятую операцию.
9. Завершить процесс аварийно во время встречи, перезапустить: `incomplete`, доступен сохранённый текст, запись выключена. Повторить при ошибке сохранения/недостатке диска.
10. Отозвать Accessibility/микрофон/системный звук, убрать модель, отключить интеграции, отозвать ключи. Убедиться в понятной диагностике и отсутствии фиктивного успеха. Проверить Windows toast click/dismiss установленного приложения и запуск при входе в ОС.
11. Пройти transcript cursor до `null` для длинной встречи, сравнить количество/порядок с экспортом; выполнить запрос на конспект через локальный Codex.

Эти ручные проверки не выполняются в Linux-облаке без интерактивных macOS/Windows и аудиоустройств. До их прохождения это preview, а не подтверждённый повседневный релиз.

Дополнительные проверки по обратной связи Preview:

1. Войти в Zoom, дождаться предложения и перевести фокус в компактное окно Meetily. Повторить после исчезновения панели кнопок Zoom. Предложение не должно ошибочно сообщать, что звонок окончен; начало записи требует повторной проверки текущего звонка. Отдельно выйти из Zoom и нажать прежнюю кнопку — запись не должна начаться.
2. Для встречи с сохранённым аудио выбрать другую установленную модель Whisper, язык `ru` и слова вроде `HRMS`, `Гермес`, `Hermes`, `Яндекс Маркет`. Сравнить результат с исходным текстом; подсказки помогают распознаванию, но не гарантируют нужное написание.
3. Проверить явное сохранение общего словаря и его наличие после перезапуска. Разовые подсказки отдельного запуска не должны добавляться в общий словарь. Для Parakeet подсказки должны быть явно недоступны.
4. Отменить повторную обработку, закрыть/открыть диалог, проверить отсутствие подмены задания и сохранность прежнего текста. Повторить с отсутствующим аудиофайлом/моделью. После успешного запуска проверить обновлённый текст и метки времени через GUI и MCP.

По следующему запросу пользователя адаптирован подход к словарным подсказкам Whisper: нормализация словаря, токенизация, ограничение 224 токенами и передача prompt tokens движку. Лицензия MIT совместима с текущим проектом; исходное уведомление `Copyright (c) 2024 Zackriya Solutions` и полный текст MIT сохранены в `LICENSE.md`, commit источника указан рядом с адаптацией. Жизненный цикл повторного распознавания и защита сохранённых данных реализованы для нашей архитектуры.

Отдельный кандидат для дальнейшей интеграции — [CLI-провайдер конспектов](https://github.com/TylerBuza/Meetily-ActuallyFree/blob/e091a7a99b0681553b8ef6bb6a8e4b3948f8a940/frontend/src-tauri/src/claude_cli/claude_cli.rs#L515): отдельный процесс для каждого запроса, существующая авторизация CLI, текст встречи через stdin, поиск бинарника и настройка явного пути. Дополнительные кандидаты — захват аудио выбранных приложений, экспорт PDF/Word и интерфейс библиотеки встреч.

Детектор не подходит как прямая замена нашим адаптерам: [Discord явно исключён](https://github.com/TylerBuza/Meetily-ActuallyFree/blob/e091a7a99b0681553b8ef6bb6a8e4b3948f8a940/frontend/src-tauri/src/meeting_detection.rs#L108), а при отсутствии Windows CAM-сигнала, включая macOS, остаётся [поиск процесса](https://github.com/TylerBuza/Meetily-ActuallyFree/blob/e091a7a99b0681553b8ef6bb6a8e4b3948f8a940/frontend/src-tauri/src/meeting_detection.rs#L226). Кроме того, его `useRecordingStop.ts` сохраняет встречу из React после ожидания сегментов; перенос этого пути отменил бы нашу независимость сохранения от GUI.

Поддержки Codex CLI в изученном форке не найдено. В текущем PR Codex получает встречи через MCP; отдельный встроенный provider дал бы кнопку генерации конспекта внутри Meetily через установленный `codex exec`. Этот provider пока не реализован. Минимальная адаптация — подключить его к существующему summary pipeline, сохранив необязательность конспектов и отдельность управления записью.

Нельзя ограничиться заменой имени `claude` на `codex`. Справка установленного Codex `0.159.0-alpha.3` подтверждает stdin, `--json`, `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, `--skip-git-repo-check` и `--sandbox read-only`; это не подтверждает поддержку тех же флагов во всех стабильных версиях и не доказывает отключение инструментов. Для выбранной поддерживаемой версии нужно проверить изоляцию инструментов/MCP, разбирать именно финальный ответ из JSONL, ограничить объём stdout/stderr и общий timeout, завершать дерево процессов при отмене. Runner Claude в форке читает вывод без лимита и после завершения процесса ждёт EOF вне timeout, поэтому его стоит переработать перед заимствованием. Нужны процессные тесты с подставным CLI: большой stdin, отмена, дочерний процесс, зависший pipe, ошибки входа и отсутствие бинарника. Живой запрос к модели при этом исследовании не выполнялся.
